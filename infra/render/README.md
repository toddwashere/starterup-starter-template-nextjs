# Render

Deploy the SaaS starter template on [Render](https://render.com) using the `render.yaml` blueprint — managed Postgres, Redis (Key Value), four web services, a background worker, and a nightly cron job.

## Prerequisites

- Render account (sign up at https://render.com)
- GitHub repo connected to your Render account
- `render` CLI optional (`npm i -g @render-com/cli`)

## Quick start

```bash
# Option A — CLI (from the repo root)
render blueprint launch

# Option B — Dashboard
# New → Blueprint → point at your GitHub repo → Render picks up render.yaml automatically
```

Render will create all services, the Postgres database, and the Key Value (Redis) instance defined in the blueprint.

## Variables to fill in after first deploy

These are marked `sync: false` in the blueprint; set them in the Render dashboard under the `platform-app-env` env group or per-service:

| Key | Description |
|---|---|
| `BETTER_AUTH_URL` | External URL of `platform-dashboard` (e.g. `https://platform-dashboard.onrender.com`) |
| `NEXT_PUBLIC_BETTER_AUTH_URL` | Same as above (browser-visible) |
| `NEXT_PUBLIC_DASHBOARD_URL` | Dashboard external URL |
| `NEXT_PUBLIC_WWW_URL` | www external URL |
| `NEXT_PUBLIC_API_URL` | public-api external URL |
| `NEXT_PUBLIC_MCP_URL` | public-mcp external URL |
| `STRIPE_SECRET_KEY` | Stripe secret key |
| `STRIPE_WEBHOOK_SECRET` | Stripe webhook signing secret |
| `SENTRY_DSN` | Sentry DSN (optional) |

`BETTER_AUTH_SECRET` is auto-generated by Render (`generateValue: true`) — no action needed.

## Cron jobs

`platform-cleanup-expired-sessions` runs daily at **03:00 UTC** and enqueues a `cleanup.expired-sessions` job into BullMQ. The `platform-workers` service picks it up.

To add more cron jobs: append another `type: cron` block to `render.yaml` and redeploy the blueprint.

## Workers

`platform-workers` receives `REDIS_URL` and `DATABASE_URL` from the shared env group — no extra wiring needed.

Tail logs via the dashboard or:

```bash
render logs --service platform-workers --tail
```

## Troubleshooting

- **Image build timeout** — Render's default build timeout is 20 min. Large monorepo images may hit this. Enable [build caching](https://docs.render.com/docker-build-caching) or split the Dockerfile into smaller stages.
- **BullMQ connection errors** — Ensure `maxmemoryPolicy: noeviction` is set on the Key Value instance (it is in the blueprint). BullMQ will fail silently or drop jobs if the policy is `allkeys-lru`.
- **Free Postgres gone after 30 days** — Switch the `databases[0].plan` value from `free` to `starter` (or higher) before the trial ends.
- **`sync: false` vars not set** — Services will start but auth/billing will be broken until all `sync: false` variables are filled in post-deploy.

See [Render Blueprint docs](https://docs.render.com/blueprint-spec) for the full spec reference.
